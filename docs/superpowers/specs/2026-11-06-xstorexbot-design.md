# xstorex bot — спецификация

Дата: 2026-11-06. Статус: одобрена владельцем 2026-11-06.

## 1. Что это

Telegram-бот, который продаёт подписку на закрытый канал с IPA-приложениями владельца. Сертификат для установки входит в подписку. Покупатель скачивает IPA из канала и сам подписывает его в Feather своим сертификатом.

Это отдельный продукт. С сайтом xstorex.ru, его кодом, API и базой бот не связан. У него свой репозиторий (`Vladpryanik11/xstorexbot`) и свой сервер.

## 2. Цели

1. Покупатель без участия владельца проходит путь от `/start` до входа в закрытый канал: выбрал тариф, оплатил, вступил.
2. Путь от UDID до сертификата включает один ручной шаг владельца. Бот передаёт данные в обе стороны и проверяет сертификат перед отправкой.
3. В закрытом канале только люди с активной подпиской. После окончания срока бот удаляет человека в течение минуты.
4. Платёж не теряется и не засчитывается дважды.
5. Владелец управляет всем из Telegram: чат заказов и меню `/admin`.

## 3. Вне рамок первой версии

- Mini App, веб-админка, сайт.
- Публикация IPA через бота. Оба канала владелец ведёт сам.
- Подпись IPA на сервере, автоматический выпуск сертификатов.
- Рассылки, статистика, промокоды, реферальная программа.
- Правка текстов из админки.
- Любой язык, кроме русского.

## 4. Решения владельца и принятые риски

| Тема | Решение |
|---|---|
| Контент | В закрытом канале только собственные IPA владельца. Владелец публикует их вручную. Взломанные приложения, «Premium»-моды и расшифрованные копии платных приложений App Store не публикуются. Бот содержимое каналов не трогает |
| Оплата | Platega (карта или СБП) и Telegram Stars |
| Сертификат | Выпускает посредник по UDID. Владелец вручную пересылает ему UDID и загружает результат в бот |
| Сервер | Отдельный новый VPS. Домен не нужен |

**Принятые риски:**

1. **Правила Telegram.** Приём рублей через Platega нарушает п. 6.2 [Условий для разработчиков ботов](https://telegram.org/tos/bot-developers): цифровые товары в ботах продаются только за Stars. Telegram может заблокировать бота. Запасной план описан в разделе 16.
2. **Сертификат после окончания подписки** продолжает работать на iPhone покупателя. Отозвать его может только посредник.
3. **152-ФЗ.** Telegram ID и @username могут считаться персональными данными. Если сервер находится за пределами России, это юридический риск владельца.

| Ссылка на вступление | Одна на всех, с включённым одобрением заявок. Владелец создаёт её в настройках канала | `CHANNEL_INVITE_LINK` |
| Канал-витрина | Публичный, описания приложений без файлов | `CATALOG_URL` |

| Чат заказов | Закрытая группа: бот и админы | `ORDERS_CHAT_ID` |
| Оферта | Страница Telegraph. Ссылка стоит в описании бота, в `/terms` и на экране тарифа | `OFFER_URL` |

| Как узнать UDID | Инструкция для покупателя | `UDID_HELP_URL` |

## 6. Сценарии покупателя

Даты покупателю показываются по московскому времени в формате `15.12.2026`.

### 6.1. `/start`

Картинка, текст из `content/start.txt` и кнопки:

| Кнопка | Действие |
|---|---|
| Купить подписку | Список тарифов (6.2) |
| Каталог | Ссылка на витрину |
| Отзывы | Ссылка на канал отзывов |
| О сервисе | Текст из `content/about.txt` |
| Поддержка | Ссылка на владельца |
| Моя подписка | Только при активной подписке (6.4) |

Кнопки идут по две в ряд, от главного к справочному:

```
[ Моя подписка ]                  ← только при активной подписке, весь ряд
[ Купить подписку ] [ Каталог ]
[ Отзывы ]          [ Поддержка ]
[ О сервисе ]                     ← весь ряд
```

При активной подписке над кнопками добавляется строка «Подписка активна до 15.12.2026».

`/start` с параметром `paid_<id платежа>` (так покупатель возвращается со страницы Platega) сразу проверяет этот платёж (7.3) и сообщает результат.

### 6.1.1. Смена экранов

Клиенты Telegram показывают удаление сообщения как рассыпание на частицы. Бот пользуется этим: при переходе старый экран удаляется, новый отправляется следующим сообщением. Сообщения не редактируются.

1. Главное меню (картинка с кнопками) при переходах не удаляется.
2. Под меню открыт не больше одного экрана: список тарифов, экран тарифа, «О сервисе» или «Моя подписка».
   - Переход на другой экран удаляет текущий и отправляет новый.
   - Кнопка главного меню удаляет открытый экран и открывает выбранный.
3. «‹ Назад»:
   - на экране тарифа удаляет его и отправляет список тарифов;
   - на списке тарифов и в «О сервисе» удаляет экран, остаётся меню.
4. Повторный `/start` удаляет старое меню, открытый экран и сообщение покупателя «/start», затем отправляет новое меню.
5. Важные сообщения не удаляются никогда: ссылка на оплату, «Оплата прошла», ссылка на вступление в канал, сертификаты, напоминания. Они не считаются экранами.

Ограничения:

- Telegram не даёт удалить сообщение старше 48 часов. Ошибка удаления игнорируется, новый экран всё равно отправляется.
- Номера сообщений меню и экрана хранятся в памяти и теряются при перезапуске. Кнопки на старых экранах продолжают работать: удаляется нажатое сообщение, если это не меню (меню — единственное сообщение с картинкой).
- Анимацию рисует клиент. На компьютере и в режиме энергосбережения частиц может не быть, сообщение просто исчезает.

### 6.2. Покупка

1. «Купить подписку» показывает кнопки включённых тарифов, по одной в ряд, по возрастанию срока; самый выгодный тариф переносится в середину списка (позиция ⌊n/2⌋ от нуля). На кнопке цена за месяц и срок: «490 ₽/мес. — 30 дней», «⭐ 290 ₽/мес. — 180 дней», «390 ₽/мес. — 90 дней». Цена за месяц — цена тарифа × 30 / дни, округлённая до рубля. Самый выгодный тариф (наименьшая цена за месяц, при равенстве — более длинный) отмечен «⭐» и окрашен в синий цвет (`style: primary`), если тарифов больше одного. Внизу кнопка «‹ Назад».
2. Экран тарифа:
   ```
   Подписка: 90 дней
   Стоимость: 1170 ₽ (390 ₽ в месяц)

   Оплачивая, вы принимаете условия оферты.
   ```
   «Оферта» в тексте — ссылка. Для 30 дней строки «в месяц» нет. Кнопки: «Оплатить картой / СБП», «Оплатить в Stars — N ⭐» (только если у тарифа задана цена в Stars), «Назад».
3. Оплата идёт по разделу 7. После успешной оплаты подписка продлевается (7.5), и бот присылает:
   - «Оплата прошла. Подписка активна до 15.12.2026»;
   - кнопку «Вступить в канал» со ссылкой `CHANNEL_INVITE_LINK`;
   - просьбу прислать UDID (8.2), если у покупателя нет выданного сертификата и открытой заявки.

### 6.3. Вступление в канал

Покупатель нажимает ссылку, и Telegram отправляет боту заявку на вступление (`chat_join_request`).

- Подписка активна — бот одобряет заявку.
- Подписки нет — бот отклоняет заявку и пишет покупателю: «Подписка не активна. Оформить: /start».

Утёкшая ссылка бесполезна: по ней вступят только подписчики.

### 6.4. «Моя подписка»

Экран показывает дату окончания подписки и состояние сертификата.

Кнопки:
- «Вступить в канал»;
- «Продлить» открывает список тарифов;
- блок сертификата:

| Состояние | Что видит покупатель |
|---|---|
| Заявок нет | «Отправить UDID» и «Как узнать UDID» |
| Заявка открыта | «Заявка №12 в работе» |
| Сертификат выдан | «Сертификат действует до 05.11.2027», кнопки «Получить сертификат ещё раз» и «Нужен новый сертификат» |

«Нужен новый сертификат» спрашивает: «Тот же iPhone» (новая заявка со старым UDID) или «Новый iPhone» (бот ждёт новый UDID). У покупателя может быть только одна открытая заявка.

### 6.5. Окончание подписки

- За 3 дня и за 1 день до конца бот присылает напоминание с кнопкой «Продлить».
- Когда срок истёк, бот удаляет человека из канала. Это бан и сразу разбан: после продления человек снова может вступить. Бот пишет: «Подписка закончилась» и показывает кнопку «Продлить».
- Людей, которых владелец добавил в канал вручную, и админов канала бот не трогает. Он удаляет только тех, у кого истекла подписка в его базе.

### 6.6. Служебные команды

- `/paysupport` — обязательна по п. 6.2.1 правил Telegram. Ответ: «По вопросам оплаты и возврата напишите в поддержку» и ссылка `SUPPORT_URL`.
- `/terms` — ссылка на оферту.

## 7. Тарифы и оплата

### 7.1. Тарифы

| Срок | Цена | В месяц | Stars |
|---|---|---|---|
| 30 дней | 490 ₽ | 490 ₽ | не задана |
| 90 дней | 1170 ₽ | 390 ₽ | не задана |
| 180 дней | 1740 ₽ | 290 ₽ | не задана |

Цены в рублях и Stars владелец меняет в админке (9.3). Сроки тарифов фиксированы. Цена в месяц считается так: цена ÷ (дни ÷ 30), с округлением до рубля.

### 7.2. Платёж

Любая оплата начинается с записи `Payment` со статусом `PENDING`. В ней фиксируются тариф, срок в днях, сумма и валюта на момент создания. Если владелец потом поменяет цену, уже созданный платёж оплачивается по своей сумме.

Неоплаченный платёж живёт сутки. Через сутки платёж в `PENDING` получает статус `EXPIRED`, платёж в `CANCELED` сохраняет свой статус, и бот перестаёт проверять оба по расписанию. Проверка по запросу покупателя (7.3) работает и после этого.

### 7.3. Platega

API: `https://app.platega.io/`, заголовки `X-MerchantId` и `X-Secret` в каждом запросе.

**Создание.** `POST /v2/transaction/process`, способ оплаты покупатель выбирает на странице Platega:

| Поле | Значение |
|---|---|
| `paymentDetails` | `{ amount: <рубли>, currency: "RUB" }`. В базе сумма хранится в копейках, в запрос уходит в рублях |
| `description` | `xstorex: подписка на 90 дней` |
| `return`, `failedUrl` | `https://t.me/<BOT_USERNAME>?start=paid_<id платежа>` |
| `payload` | id платежа |
| `metadata.user_email` | `<telegram_id>@telegram.org`, как требует Platega для магазинов в Telegram |
| `metadata.userId` | Telegram ID |

Из ответа бот сохраняет `transactionId` и ссылку на оплату. Покупатель видит кнопки «Перейти к оплате» и «Я оплатил». Ссылка живёт 15 минут. Если она устарела, повторное нажатие «Оплатить картой / СБП» создаёт новый платёж.

Если Platega откажется принимать адрес `t.me` в `return` и `failedUrl`, вместо него подставляется `OFFER_URL`. Это проверяется первым же тестовым платежом.

**Проверка статуса.** Уведомлений (колбэков) бот не принимает. Статус он узнаёт сам запросом `GET /transaction/{transactionId}`:

| Когда | Как часто |
|---|---|
| Первые 20 минут после создания | Каждые 10 секунд |
| До суток после создания | Раз в 5 минут |
| Покупатель нажал «Я оплатил» или вернулся по `paid_<id>` | Сразу, даже если платёж уже `CANCELED` или `EXPIRED` |
| Оплаченные платежи за последние 30 дней | Раз в сутки, поиск чарджбэков |

**Что делать со статусом:**

| Статус Platega | Действие |
|---|---|
| `CONFIRMED`, сумма и валюта совпали | Зачислить (7.5) |
| `CONFIRMED`, сумма или валюта не совпали | Не зачислять, предупредить в чате заказов |
| `PENDING` | Ждать |
| `CANCELED` | Отметить. Проверять дальше до суток: Platega изредка подтверждает отменённый платёж |
| `CHARGEBACKED` у оплаченного | Как возврат (7.6), предупредить в чате заказов |
| Любой другой (`DISPUTED`, `PARTIALLY_REFUNDED` и т. п.) | Доступ не менять, предупредить в чате заказов один раз на каждый новый статус |

Ответ разбирается терпимо: поля принимаются и в `camelCase`, и в `PascalCase`.

### 7.4. Telegram Stars

1. «Оплатить в Stars» вызывает `sendInvoice`: валюта `XTR`, одна позиция на сумму тарифа в Stars, `payload` — id платежа.
2. `pre_checkout_query`: бот подтверждает списание, только если платёж существует, принадлежит этому покупателю, ещё в `PENDING`, не старше суток и сумма совпадает. Иначе отказ с текстом «Счёт устарел, выберите тариф заново». Ответить нужно в пределах 10 секунд.
3. `successful_payment`: бот сверяет `payload` и сумму, сохраняет `telegram_payment_charge_id` (без него звёзды нельзя вернуть) и зачисляет платёж (7.5).
4. Служебное сообщение `refunded_payment` (возврат, сделанный Telegram) обрабатывается как возврат (7.6).

### 7.5. Зачисление платежа

Одна транзакция базы:

1. Платёж получает статус `PAID` и отметку `appliedAt`, только если `appliedAt` ещё пуст. Если отметка уже стоит, ничего не происходит. Это защищает от двойного продления.
2. `Subscription.endsAt = max(сейчас, endsAt) + дни`. Отметки о напоминаниях и об удалении из канала сбрасываются.

После транзакции бот пишет покупателю (6.2, шаг 3) и отправляет в чат заказов сообщение об оплате.

Если покупатель оплатил дважды, оба платежа продлевают подписку.

### 7.6. Возврат

Возврат делает админ из карточки подписчика (9.3) после подтверждения «Вернуть 1170 ₽ @user и закрыть подписку?».

- Stars: `refundStarPayment(user_id, telegram_payment_charge_id)`.
- Platega: `GET /transaction/{id}/cancel-supported`, затем `POST /transaction/{id}/cancel` (полный возврат).

После возврата платёж получает статус `REFUNDED`, подписка закрывается (`endsAt = сейчас`), и в течение минуты бот удаляет человека из канала. Возврат не по решению админа (чарджбэк в Platega, `refunded_payment` от Telegram) даёт тот же результат, только статус платежа — `CHARGEBACK`.

## 8. Сертификаты

### 8.1. Формат UDID

Принимаются два формата:
- 40 шестнадцатеричных символов (старые iPhone);
- 8 и 16 шестнадцатеричных символов через дефис, например `00008030-001A35E80C42802E`.

Пробелы по краям обрезаются, буквы приводятся к верхнему регистру. Строку другого вида бот не принимает и показывает подсказку со ссылкой `UDID_HELP_URL`.

### 8.2. Заявка

Бот ждёт UDID от покупателя, если подписка активна, открытой заявки нет и выполнено одно из условий:
- выданного сертификата ещё нет;
- покупатель нажал «Нужен новый сертификат» → «Новый iPhone».

Подходящий UDID создаёт заявку `CertRequest` со статусом `OPEN` и номером. Покупатель видит «Заявка №12 принята». В чат заказов уходит сообщение:

```
Заявка на сертификат №12
@user (ID 123456789), подписка до 15.12.2026
UDID: 00008030-001A35E80C42802E
```

UDID набран моноширинным шрифтом, чтобы его можно было скопировать одним нажатием. Под сообщением кнопки «Выдать сертификат» и «Попросить UDID заново». Вторая закрывает заявку со статусом `REJECTED` и просит покупателя прислать UDID ещё раз.

### 8.3. Выдача

1. Админ нажимает «Выдать сертификат» в чате заказов или в меню «Заявки». Бот пишет ему в личку: «Заявка №12, @user. Пришлите сертификат».
2. Админ пересылает боту то, что прислал посредник: файлы `.p12` и `.mobileprovision` по отдельности или один ZIP-архив. Порядок любой, файлы бот различает по расширению.
3. Бот спрашивает пароль, админ отправляет его обычным сообщением.
4. Бот проверяет:
   - пароль открывает `.p12`;
   - UDID покупателя есть в списке `ProvisionedDevices` профиля;
   - сертификат из `.p12` есть в списке `DeveloperCertificates` профиля;
   - срок действия профиля и сертификата не истёк.

   Если проверка не прошла, бот пишет, что именно не так, и ждёт исправленные файлы или пароль. Покупатель ничего не получает.
5. Бот показывает сводку «@user, сертификат действует до 05.11.2027» и кнопки «Отправить» и «Отмена». Срок берётся как более ранняя из двух дат: окончание профиля или окончание сертификата.
6. После нажатия «Отправить» покупатель получает:
   - `.p12`;
   - `.mobileprovision`;
   - пароль под спойлером;
   - инструкцию для Feather из `content/feather.txt`.

   Заявка получает статус `ISSUED`, файлы и пароль сохраняются зашифрованными. Сообщение в чате заказов дополняется строкой «Выдан 06.11.2026 14:32, админ @owner».
7. «Отмена» на любом шаге сбрасывает загрузку. Заявка остаётся открытой.

Состояние загрузки (какие файлы и пароль уже получены) хранится только в памяти процесса и живёт 30 минут. После перезапуска бота админ начинает загрузку заново. Так незашифрованный сертификат никогда не попадает в базу.

**Ограничения на файлы.** Каждый файл не больше 5 МБ. В архиве распакованные файлы вместе не больше 5 МБ и не больше 20 записей. Архив распаковывается в памяти, на диск ничего не пишется. Если в архиве нет `.p12` или `.mobileprovision` либо таких файлов больше одного, бот сообщает об этом и ждёт другой архив.

### 8.4. Хранение

`.p12`, `.mobileprovision` и пароль шифруются AES-256-GCM: ключ `CERT_ENCRYPTION_KEY` (32 байта, base64), случайный 12-байтовый IV на каждую запись. Формат записи: `версия формата (1 байт, сейчас 1) | IV | тег | шифротекст`.

Сертификат хранится целиком, а не ссылкой Telegram (`file_id`). Причина: `file_id` работает только у того бота, который получил файл, и после переезда на запасного бота (раздел 16) выданные сертификаты пропали бы.

«Получить сертификат ещё раз» расшифровывает последнюю выданную заявку и отправляет покупателю то же, что в 8.3, шаг 6.

## 9. Админка и чат заказов

### 9.1. Права

Админы — Telegram ID из `ADMIN_IDS`. Права проверяются при каждом действии, а не только скрытием меню. Нажатие админской кнопки не админом даёт ответ «Нет прав». Меню `/admin` работает только в личке с ботом.

### 9.2. Чат заказов

Бот пишет сюда:

| Событие | Содержание |
|---|---|
| Оплата | @user, тариф, сумма, способ (Platega, Stars или вручную), подписка до |
| Заявка на сертификат | 8.2 |
| Возврат, чарджбэк | @user, сумма, способ, подписка закрыта |
| Странный статус или сумма Platega | 7.3 |
| Бот потерял права админа в закрытом канале | Сразу (по обновлению `my_chat_member`) |
| Не удалось удалить из канала или одобрить заявку | После 5 неудачных попыток |
| Неожиданная ошибка | Короткое описание. Одинаковые ошибки не чаще раза в 10 минут |

### 9.3. Меню `/admin`

1. **Заявки.** Открытые заявки по одной, с теми же кнопками, что в чате заказов.
2. **Подписчики.** Поиск по @username или Telegram ID. Карточка подписчика: срок подписки, список платежей, сертификат. Действия:
   - «Добавить дни»: N дней, подписка продлевается как в 7.5, в истории появляется платёж `MANUAL` на 0 ₽;
   - «Завершить подписку»: `endsAt = сейчас`, без возврата денег;
   - «Вернуть деньги» у конкретного платежа (7.6).
3. **Тарифы.** У каждого тарифа: цена в рублях, цена в Stars (пустая цена скрывает кнопку Stars), «включён» или «скрыт».

Перед «Завершить подписку» и «Вернуть деньги» бот просит подтверждение.

### 9.4. Журнал

Каждое действие админа записывается в `AdminLog`: кто, что, с кем, когда, подробности. Пароли и файлы сертификатов в журнал не попадают.

## 10. Архитектура

### 10.1. Стек

Node 24, TypeScript, pnpm, grammY (`@grammyjs/runner`, `@grammyjs/auto-retry`), Prisma и PostgreSQL 17, zod для настроек, pino для логов, node-forge для `.p12`, fflate для ZIP, plist для профиля. Тесты на Vitest, линтер и форматирование — Biome.

### 10.2. Процесс

Один процесс, HTTP-сервера нет:

- **Бот** получает обновления через long polling (`getUpdates`): `message`, `callback_query`, `pre_checkout_query`, `chat_join_request`, `my_chat_member`.
- **Планировщик** (раздел 12) работает внутри того же процесса.

Запускается ровно один экземпляр: второй получил бы от Telegram ошибку 409. Задачи планировщика дополнительно защищены `pg_try_advisory_lock`, чтобы одна задача не запускалась поверх незавершённой предыдущей.

## 11. Данные

PostgreSQL, Prisma. Суммы в рублях хранятся в копейках, время — в UTC.

| Таблица | Поля |
|---|---|
| `User` | `id` (Telegram ID, bigint), `username`, `firstName`, `createdAt`, `blockedAt` (заблокировал бота), `udidExpectedAt` (ждём новый UDID) |
| `Plan` | `id`, `days` (уникально), `priceRub`, `priceStars` (может быть пустой), `enabled`, `sort` |
| `Subscription` | `userId` (PK), `endsAt`, `reminded3dAt`, `reminded1dAt`, `removedAt`, `removeAttempts`, `updatedAt` |
| `Payment` | `id` (uuid), `userId`, `planId` (пусто у `MANUAL`), `provider` (`PLATEGA` / `STARS` / `MANUAL`), `days`, `amount`, `currency` (`RUB` / `XTR`), `status` (`PENDING` / `PAID` / `CANCELED` / `EXPIRED` / `REFUNDED` / `CHARGEBACK`), `providerStatus` (последний статус у Platega), `providerPaymentId` (уникально), `paymentUrl`, `createdAt`, `paidAt`, `appliedAt`, `lastCheckedAt`, `createdByAdminId` |
| `CertRequest` | `id` (номер заявки), `userId`, `udid`, `status` (`OPEN` / `ISSUED` / `REJECTED`), `p12Enc`, `profileEnc`, `passwordEnc`, `certExpiresAt`, `ordersChatMessageId`, `createdAt`, `issuedAt`, `issuedByAdminId` |
| `AdminLog` | `id`, `adminId`, `action`, `targetUserId`, `details` (json), `createdAt` |

Ограничения:
- одна открытая заявка на покупателя: частичный уникальный индекс `CertRequest(userId) WHERE status = 'OPEN'`, задаётся SQL-миграцией;
- `Payment.providerPaymentId` уникален, поэтому один и тот же платёж Telegram или Platega нельзя записать дважды.

Начальные данные: три тарифа из 7.1.

## 12. Планировщик

| Задача | Как часто | Что делает |
|---|---|---|
| Проверка платежей | Каждые 10 секунд | Проверяет платежи Platega, которым пора по расписанию 7.3. Неоплаченные платежи (Platega и Stars) старше суток закрывает по правилу 7.2 |
| Окончание подписок | Раз в минуту | Удаляет из канала тех, у кого `endsAt` прошёл, а `removedAt` пуст, и пишет им (6.5). При ошибке увеличивает `removeAttempts`, на пятой попытке предупреждает в чате заказов |
| Напоминания | Раз в минуту | За 3 дня и за 1 день до `endsAt`, если отметка ещё не стоит |
| Чарджбэки | Раз в сутки, 03:00 МСК | Перепроверяет оплаты Platega за 30 дней |
| Резервная копия | Раз в сутки, 04:00 МСК | Раздел 13.3 |

Если покупатель заблокировал бота (ошибка 403), бот ставит `User.blockedAt` и больше ему не пишет. Удаление из канала при этом всё равно выполняется. Отметка снимается, когда покупатель снова пишет боту.

## 13. Надёжность

### 13.1. Ошибки

| Ситуация | Поведение |
|---|---|
| Telegram отвечает 429 | `auto-retry` ждёт `retry_after` и повторяет запрос |
| Platega недоступна при создании платежа | «Не удалось создать платёж, попробуйте через минуту или оплатите в Stars» |
| Platega недоступна при проверке статуса | Повтор в следующем цикле |
| Не удалось одобрить заявку на вступление | Повтор при следующем нажатии ссылки. Если ошибка не связана с правами, предупреждение в чате заказов |
| Неожиданная ошибка в обработчике | Покупателю «Что-то пошло не так, попробуйте ещё раз», подробности в лог, короткое сообщение в чат заказов |
| Падение процесса | Docker перезапускает контейнер (`restart: unless-stopped`) |

### 13.2. Логи

JSON в stdout (pino), ротация средствами Docker: 10 МБ × 5 файлов. Токен бота, ключи Platega, ключи шифрования, пароли сертификатов и содержимое файлов вырезаются из логов. Токен вырезается и из текста ошибок grammY.

### 13.3. Резервная копия

1. `pg_dump -Fc` (клиент PostgreSQL установлен в образ бота).
2. Шифрование AES-256-GCM ключом, выведенным через scrypt из `BACKUP_PASSPHRASE`. Это отдельный секрет, не `CERT_ENCRYPTION_KEY`.
3. Файл отправляется владельцу в личку (`OWNER_ID`). Если он больше 45 МБ, бот не отправляет его и предупреждает в чате заказов.
4. На сервере хранятся копии за последние 14 дней (том `backups`).

Ежедневная копия заодно сообщает владельцу, что бот жив: если она не пришла, нужно проверить сервер. Расшифровка и восстановление описаны в README (`pnpm backup:decrypt <файл>`).

## 14. Безопасность

- **Секреты** хранятся только в `.env` на сервере с правами `600`: `BOT_TOKEN`, `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET`, `CERT_ENCRYPTION_KEY`, `BACKUP_PASSPHRASE`, `POSTGRES_PASSWORD`. В git лежит только `.env.example` с пустыми значениями.
- **Проверка прав** на каждое действие (9.1).
- **Защита от подмены кнопок.** Данные кнопок (`callback_data`) проверяются: покупатель открывает и оплачивает только свои платежи и заявки, даже если модифицированный клиент подставит чужой номер.
- **Ввод:** проверка UDID (8.1), ограничения на файлы и архивы (8.3).
- **Сертификаты:** шифрование (8.4). Незашифрованные данные есть только в памяти во время загрузки и отправки.
- **Сервер:**
  - входящие соединения закрыты, кроме SSH; вход только по ключу;
  - автоматические обновления безопасности;
  - контейнер бота работает не от root, база доступна только внутри Docker-сети.
- **Зависимости:** `pnpm audit --prod` в CI.

## 16. Деплой

- **Сервер:** новый VPS с Docker. `docker compose` из двух сервисов: `bot` и `postgres` (17, данные в томе). Порты наружу не публикуются.
- **Обновление:** `git pull` и `docker compose up -d --build`. Миграции применяются при старте контейнера (`prisma migrate deploy`).
- **CI (GitHub Actions)** на pull request и push в `main`: Biome, проверка типов, модульные тесты, интеграционные тесты с сервисом PostgreSQL, `pnpm audit --prod`, сборка Docker-образа.
- **Запасной план при блокировке бота:**
  1. Создать нового бота в BotFather.
  2. Заменить `BOT_TOKEN` и `BOT_USERNAME`, перезапустить.
  3. Сделать нового бота админом закрытого канала и чата заказов.
  4. Объявить новую ссылку в витрине.

  Подписки, платежи и сертификаты сохраняются, потому что живут в нашей базе.

**Подготовка к запуску (делает владелец):**

1. Создать бота в BotFather, указать описание со ссылкой на оферту и команды `/start`, `/paysupport`, `/terms`.
2. Создать закрытый канал, ссылку с одобрением заявок, добавить бота админом с правами «Пригласительные ссылки» и «Блокировка участников».
3. Создать чат заказов и добавить туда бота. Каждый админ пишет боту `/start` в личке, иначе бот не сможет писать ему при выдаче сертификата и отправке резервных копий.
4. Получить ключи Platega.
5. Подготовить VPS и заполнить `.env` и `content/`.
6. Задать цены в Stars в админке, если нужна оплата звёздами.

## 17. Тестирование

Разработка ведётся по TDD: сначала падающий тест.

- **Модульные (Vitest):**
  - расчёт сроков и цены в месяц;
  - проверка UDID;
  - разбор ответов Platega (оба регистра полей, все статусы);
  - сверка суммы;
  - шифрование и расшифровка;
  - разбор `.p12`, профиля и ZIP, все проверки 8.3, ограничения размеров.
- **Интеграционные, с настоящей PostgreSQL:**
  - зачисление платежа и повторное подтверждение;
  - возврат и чарджбэк;
  - окончание подписки и удаление из канала, повтор после ошибки;
  - напоминания;
  - одобрение и отклонение заявок на вступление;
  - заявки на сертификат: одна открытая на покупателя, выдача, повторная выдача.
- **Диалоги бота:** обновления подаются в `bot.handleUpdate`, исходящие запросы к Telegram перехватываются и проверяются. Platega и часы заменены поддельными реализациями.
- **Тестовые сертификаты** генерируются в тестах через node-forge: самоподписанный сертификат, `.p12` и подписанный профиль. Настоящих сертификатов в репозитории нет.

**Ручная проверка перед запуском:**
- отдельный тестовый бот и тестовый канал;
- оплата Stars в тестовой среде Telegram;
- один реальный платёж Platega на минимальную сумму с последующим возвратом;
- полный путь: покупка → вступление → UDID → выдача сертификата → установка IPA в Feather → окончание подписки.

## 18. Этапы реализации

Предлагаемый порядок. Каждый этап — отдельный план.

1. **Каркас.** Репозиторий, CI, настройки, база и тарифы, `/start` с кнопками, «О сервисе», `/terms`, `/paysupport`.
2. **Подписка и Stars.** Платежи, зачисление, оплата в Stars, вступление в канал по заявке, «Моя подписка».
3. **Platega.** Создание платежа, проверка статусов, чарджбэки.
4. **Сертификаты.** UDID, заявки, чат заказов, выдача с проверками, повторная выдача.
5. **Админка.** `/admin`: заявки, подписчики, тарифы, возвраты, журнал.
6. **Эксплуатация.** Окончание подписок и напоминания, резервные копии, Docker Compose, README, ручная проверка и запуск.
